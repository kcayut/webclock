## 管理員登入與裝置授權

既有自架安裝保持自用模式。需要逐台授權隔離時，先依下方備份流程停止所有寫入者並備份，再以服務帳號執行 `./venv/bin/python scripts/manage_auth.py --state-dir /path/to/webclock_state setup --username admin --enable-managed`，互動輸入至少 12 字元密碼。請換成實際 state 路徑；重啟後以 HTTPS 開 `/admin` 登入。舊 `--enable-managed-test` 仍相容，未提供明確旗標不會切換模式。舊名稱、能力、ACK 與內容保留，但舊自報 ID／共用 token 不會升格為裝置授權；顯示端須以六碼重新加入。`reset-password` 使用相同 state 路徑，清除所有管理 session；登入最多 8 小時，登出不撤銷獨立裝置憑證。

帳密模式下，未加入裝置仍顯示時間日期，但不取得私人事件／鬧鐘；管理登入不能替代裝置認證。六碼也不能登入管理員。儲存與授權邊界見 [B0–B1 契約](b0-b1-contract.md)，現行端點見[裝置 API](server-api.md)。

完整主機備份含身份和秘密且未加密；歷史還原會輪換管理簽章／邀請秘密、清 session／待加入嘗試、關閉邀請、使裝置憑證失效，保留群組內容與觀察記錄。帳密安裝不可由舊備份退回免登入。更新即時回滾則保留最新授權資料；舊程式無法理解時維持停止，需主機復原。管理頁 version 1 匯出仍只含 settings／notes。

### 群組設定與裝置加入

1. 在 `/schedules#devices` 建立群組，或明確確認「沿用現有內容建立預設群組」以帶入既有顯示設定與內容選擇。新建群組預設不選任何內容。
2. 為各欄選擇繼承或自訂，並選取既有行事曆、文字提醒與鬧鐘後儲存。`false`、亮度 `0` 與空內容選擇都會保留；鬧鐘仍依台灣時間計算，與群組顯示時區分開。
3. 產生六碼加入碼，設定可加入台數（預設 5、範圍 1–100）；有效期為 10 分鐘。畫面顯示期限及剩餘名額，明文只在產碼後顯示；切換群組或重載不會使碼失效，但如需再次查看，須重新產碼。關閉或重產邀請不會移除已加入成員。
4. 在目標瀏覽器開啟同一伺服器的時鐘 `/`，按「加入顯示群組」。待 Cookie 確認完成後輸入六碼；成功後裝置取得獨立身份並自動套用群組。不能從公開 Pages 或其他來源的時鐘加入。

行事曆可依「來源 → 週期系列 → 單次行程」展開選取。來源或系列全選包含未來行程；下層會顯示已勾選且停用，先取消上層全選才能個別挑選。目錄列出未來 366 天，範圍外已選項目仍保留；讀取失敗也不會清空選取。按住 Shift 點選同層另一個可用項目，可將兩者之間目前可見、可操作的項目一起設為最後點選項目的新勾選狀態；文字提醒與鬧鐘選單也支援。

群組面板會定期更新狀態，並保留本頁內切換群組、語言、慢速儲存及讀取失敗時的草稿與輸入位置；重新載入整頁不會保存未送出的草稿或加入碼。成員的授權狀態與最後觀察分開顯示，未回報資料維持未知。可對個別成員按「刪除授權」並確認；可在裝置卡片移至同一管理者的啟用群組，或停用／恢復裝置；有成員的群組不能刪除。

已加入的時鐘可在連線面板按「退出群組」。退出或管理員刪除授權成功後，該裝置會從群組成員及裝置列表移除，舊憑證立即失效，重新加入需加入碼；其他裝置、本機提醒不受影響，原邀請已用名額不退還。遠端離線裝置仍按最長 300 秒租約停止私人內容，不能保證立即清除；儲存失敗不視為操作完成。

在裝置卡片展開「此裝置的顯示設定」，可自訂亮度、黑畫面、顯示時區、12／24 小時制與顯示語言；夜間模式整組繼承或自訂。每欄列出伺服器目前生效值與來源，不代表裝置已實際套用。選「沿用群組」並保存即移除覆寫，上層後續變更會自動跟隨；移組保留單台覆寫，其餘改用新群組設定。未儲存草稿在輪詢、切換管理語言及保存失敗時保留；若其他頁面或上層設定已變更，會拒絕舊版本保存，核對後可確認放棄草稿並重新載入。此功能適用已取得逐台身份的裝置，舊 self 紀錄不能只憑自報 ID 設定。

在同一張卡片展開「此裝置的內容指派與預覽」，可分別為行事曆、文字提醒及鬧鐘選擇「沿用群組」或「自訂」。自訂清單取代該類群組清單，空清單表示不提供該類內容；行事曆的來源、系列、單次與排除例外一起繼承或取代。保存「沿用群組」即移除該類覆寫。移組保留已明確保存的單台自訂內容，其餘重新跟隨新群組，不複製舊群組清單。下方列出伺服器生效項目與來源，不能當作裝置已顯示或已響鈴的回報；已刪除項目不會擴大成其他內容。這些設定引用既有 ID，不更改共用行事曆或原始鬧鐘。

全體顯示設定、群組設定、逐項套用群組及單台內容保存都有版本衝突檢查。其他管理頁或上層已修改時，保存會拒絕並保留草稿；確認放棄後才重新載入最新設定，再重新編輯。一般輪詢與切語言不會放棄草稿；重新載入期間新輸入的內容也會保留。完整主機備份保留單台覆寫，歷史還原仍使舊憑證失效；管理頁 JSON 備份不包含群組與裝置設定。

已加入的時鐘取得依「單台裝置 > 群組 > 全體預設」計算的顯示設定，內容由各類單台自訂或所屬群組的明確指派決定。短暫離線可在最長 5 分鐘授權租期內沿用本次載入的私人資料；確認未授權或租期到期後會清除私人事件、公告與鬧鐘佇列並停止目前網頁響鈴，時間日期與瀏覽器本機提醒仍可使用。這不代表離線重新開頁或 iOS 背景／鎖屏響鈴已獲保證；初代 iPad mini／iOS 9 與 ESP 韌體的新身份流程仍須各自驗收。

## 公開時鐘

直接開啟 [WebClock 線上時鐘](https://kcayut.github.io/webclock/) 即可使用，不需要帳號或伺服器。時間與時區跟隨裝置，日期與星期使用繁體中文。建議將平板橫放；iPad Safari 可用「分享 → 加入主畫面」建立入口。

WebClock 最初為初代 iPad mini 設計，時鐘頁以舊平板能穩定顯示時間為優先。若要持續顯示，請在裝置設定中調整自動鎖定與螢幕亮度。

不想安裝 Server，也可[下載 ZIP，解壓縮後在電腦直接開啟 `index.html`](installation.md#offline-download)，保留同層 `static` 資料夾即可作為離線時鐘。平板則先在線上時鐘底部看到「已可離線開啟」，再測試從相同網址／圖示斷網重開；清除網站資料或快取被回收後需重新準備。iPad mini 1／iOS 9 僅可先在線載入並保持前景，不能靠此快取離線重開。完整步驟與各裝置限制見[免安裝與離線使用](installation.md#no-server)。

## 自行架設

自行架設版提供以下入口：

- `/`：時鐘頁。
- `/admin`：顯示設定、行事曆、文字提醒、公告、備份與還原。
- `/schedules`：網頁鬧鐘與裝置同步狀態。

Docker 預設使用主機的 `80` 連接埠；Linux 安裝腳本與手動執行預設為 `5000`。完整的快速安裝命令在 [安裝指南](installation.md)。`.env` 的基本設定如下：

```env
PORT=5000
HOST=0.0.0.0
WEBCLOCK_LANGUAGE=zh-TW
```

`WEBCLOCK_LANGUAGE` 設定首次啟動的顯示語言，可設為 `zh-TW`、`en` 或 `ja`。管理側欄的語言切換只影響目前瀏覽器 session 的管理介面，保留未送出草稿，不會改變時鐘。`/admin` 顯示設定的「全體預設顯示語言」才會儲存至 `webclock_state/settings.json`，優先於部署預設值；群組可繼承此值或另外指定顯示語言。

管理側欄的「外觀」提供太陽（淺色）與月亮（深色）圖示按鈕，選中的按鈕會標亮，預設淺色；左側導覽和右側內容共用配色。選擇保存在目前瀏覽器、同一網站的 `localStorage`，供 `/admin` 與 `/schedules` 共用，重開仍保留；不會改變主時鐘或伺服器的顯示設定。切換配色不會重新載入頁面，可保留未送出的表單。

行事曆網址直接在管理頁輸入，不必寫入 `.env`。舊安裝的 `ICAL_URL` 可繼續使用，直到第一次在管理頁儲存新的行事曆來源。

## 行事曆與文字提醒

在 `/admin` 的「行事曆與提醒」展開「行事曆來源設定」，可新增並命名 Google、Apple iCloud 或其他 ICS 來源。可同時使用多個來源。網址預設遮蔽，按眼睛才會顯示；儲存後會重新遮蔽。

「來源設定」與「顯示來源」分開儲存：取消顯示不會刪除網址，也不會改變鬧鐘使用的來源。網址保存在 `webclock_state/calendar.json`，不會出現在公開時鐘、狀態 API 或管理頁下載的 JSON 備份中。請勿將這個檔案或私人網址提交到公開儲存庫。

### 選取行程與顯示區間

「時鐘顯示的來源」可展開行事曆，選取單次行程或整個週期系列；同層可用 Shift 連續選取。儲存後，勾選的行程會與文字提醒依時間排列在「目前列表」；週期系列列出下一次發生時間，目錄以未來一年為範圍。

行程預設在發生當日顯示。展開項目的「顯示區間」可改為提前幾天、幾小時或幾分鐘，並選擇在行程結束或當日結束時停止顯示；單次行程也可指定起訖日期時間。系列設定會依每次實際發生時間重新計算，改期後也會跟著調整。區間包含開始、不包含結束，依管理頁的顯示時區計算。這些設定只改變 WebClock 顯示，不會修改 Google 原始行程或鬧鐘。群組仍只會取得自己勾選的內容。

「目前列表」的每筆文字提醒、行事曆與鬧鐘項目右側會列出套用的群組。在項目的編輯區可勾選個別群組或「全部目前群組」，並按「儲存套用群組」；群組指派與其他編輯分開儲存，全部不包含日後新增的群組。系列的部分指派會明確標示，未操作的部分選取會保留。即使群組勾選整份行事曆，也能移除單一行程而保留其他與未來行程。裝置管理的文字提醒提供「全選目前提醒」，鬧鐘與裝置排程排列在下一區塊。

### Apple iCloud

1. 開啟 [iCloud 行事曆](https://www.icloud.com/calendar/)並登入。
2. 開啟行事曆旁的資訊按鈕，啟用「公開行事曆」並複製連結。
3. 將 `webcal://` 或 HTTPS 連結貼到 WebClock 後儲存。

WebClock 約每 5 分鐘唯讀更新一次，不需要 Apple 帳號或密碼，也不會同步 Apple「提醒事項」App。拿到公開連結的任何人都能讀取內容；建議建立只放時鐘行程的獨立行事曆，不使用時就停止公開共享。畫面上的網址遮蔽不會改變連結權限。

### 文字提醒

手動提醒可指定日期與時間，或設定每日／每週的顯示時段。未勾選星期代表每天；跨午夜時段歸屬開始日。開始與結束不可相同，兩欄清空可取消時段限制。時間範圍包含開始、不包含結束，並依後台時區計算。

到期提醒只會隱藏，不會自動刪除。「暫停」會保留內容但停止顯示，之後可直接恢復。時鐘頁與伺服器短暫斷線時，會沿用瀏覽器保存的顯示設定及本機提醒；行事曆與伺服器提醒在重新連線後恢復。

### 指定群組或裝置的公告

在 `/admin#announcements-title` 的「文字提醒與公告」選擇種類「公告」，輸入文字後勾選指定群組或裝置。也可先不選對象保存，未選對象時不發送。群組對象依裝置目前所屬群組判定；指定裝置則沿用該裝置身份。只有仍有有效授權的對象會收到，同時符合群組與裝置條件也只顯示一次。公告有自己的對象選擇，不使用一般文字提醒的「儲存套用群組」。

公告沿用指定日期、日期區間、每日／每週時段、暫停與恢復；也可選填「到期時間」，以後台時區保存。空白表示沒有額外的絕對到期限制，原顯示時段與暫停仍有效；到期只隱藏，不刪除內容。對象已刪除時，編輯器保留原選取並標示，取消失效對象後才可保存；保存失敗保留文字、對象與到期草稿。

時鐘透過既有輪詢取得公告，在獨立區域顯示，不遮蔽時間、不取代事件輪播，也不發出鬧鐘。黑畫面與亮度設定同樣套用。公告只保留於本次開頁的記憶體；到期、顯示時段結束、失去授權或租約到期即清除，離線時最長保留目前快照 5 分鐘，不能靠重新開頁恢復。匿名時鐘、公開 Pages 及舊 schema 2／ESP 排程不接收公告；初代 iPad mini／iOS 9 的實機顯示仍待驗收。

管理頁 JSON 備份會隨 `notes` 保留公告對象與到期時間，但不包含群組、裝置授權或私人來源網址；匯入到其他安裝不會替不存在的 ID 建立對象。完整主機備份保留相關資料，歷史還原仍撤銷舊裝置憑證。

### 瀏覽器本機提醒與連線面板

在時鐘頁左下角的連線狀態按鈕開啟面板，可填寫提醒文字及選填時間，再新增或刪除。這些提醒保存在目前網站、目前瀏覽器的 `localStorage`，在伺服器無法連線時顯示；時間只是顯示文字，不會發聲，也不會在該時間後自動消失。目前新增的提醒沒有指定日期，會保留到手動刪除；修改內容需刪除後重新新增。

本機提醒不會上傳、跨裝置同步或包含在伺服器備份中，清除網站資料會遺失。它與 `/admin` 的伺服器「本地提醒」來源不同，不能作為行事曆聯動鬧鐘的來源。重新連線成功後，時鐘恢復顯示伺服器行程與提醒，本機資料仍保留在面板。

同一面板可儲存 Server URL，並按「立即重連」測試連線；只儲存網址不代表連線成功，以面板回報為準。改用不同來源（協定、主機或連接埠）開啟時鐘，會使用另一個網站儲存空間。本機提醒保存與離線重新開頁是兩件事；後者仍須下方的離線快取條件。

## 行事曆聯動鬧鐘

鬧鐘可獨立選擇一個或多個行事曆來源，包含 `/admin` 的伺服器本地提醒：

- **依行程時間響鈴：**可提前 0–1440 分鐘；沒有時間的全天事項不觸發。
- **當天有行程才響：**只要當天任一所選來源有行程，就在鬧鐘設定的固定時間觸發；全天與跨日行程也算。

鬧鐘來源與時鐘顯示來源互不影響。星期、指定日期與台灣假日條件仍會套用，並依實際響鈴的台灣日期判斷。來源讀取失敗或被移除時，該來源不產生響鈴，其他可讀取來源仍可使用。

來源選好後，可指定某個行程，並在重複行程中選擇「單次」或「整個系列」；未指定時會跟隨所選來源全部行程。單次聯動跟隨原始行程識別值，行程改期後會跟著更新，取消後不會改抓其他行程；系列聯動跟隨該系列各次行程。訂閱更新可能需要等候最長約 5 分鐘，請重新查看下一次響鈴預覽。

## 在 iPad 使用網頁鬧鐘

1. 在 `/schedules` 新增鬧鐘，設定時間與星期或日期；星期旁的「每天」可全選七天，全選後隱藏，取消任一天即重新出現。可選鐘聲、嗶聲、電子音、和弦鈴、輕快旋律、急促嗶聲、聲納或靜音；每個鬧鐘有獨立的 0–100% 音量，預設 100%，試聽使用相同音量，0% 保留畫面提醒。
2. 每天、星期與指定日期規則可選擇跳過台灣假日；補班日仍視為工作日。「只在假日」不能同時選擇「跳過假日」。
3. 在要播放聲音的 iPad 開啟時鐘頁，點小鈴鐺啟用聲音，確認聽到短音。每次重新開啟或重新整理都要再啟用。
4. 響鈴時分兩次點擊，可停止目前頁面的這一次；不會刪除排程或停止其他裝置。

請保持 Safari 在前景、螢幕開啟，並確認音量與靜音設定。iOS 鎖屏、切換 App 或分頁後可能中斷網頁音訊與計時，因此不保證在背景或鎖屏時響鈴。靜音鬧鐘仍會顯示紅邊提示。

時鐘頁約每 15 秒更新下一次鬧鐘。短暫斷線時，已載入的下一次仍可觸發；重新開頁或取得後續週期需要恢復連線。超過 60 秒才恢復處理的過期鬧鐘不補響。假日資料涵蓋範圍外的日期會維持未知，不會猜測。

## 下一事件、暫停與恢復

`/schedules` 摘要顯示下一個鬧鐘；新增／編輯視窗顯示目前台灣時間、下一次響鈴及剩餘時間。主時鐘的行程／提醒區仍是輪播文字，沒有事件倒數；預覽和倒數也不是已執行或已響鈴的證明。

固定時間的重複鬧鐘關閉開關時，可選「暫停一次」或永久停用。暫停一次會列出略過的時刻及恢復倒數，略過時刻過後恢復啟用顯示，下一次響鈴仍按原規則計算。暫停期間重新啟用可提前恢復；永久停用則需手動啟用。指定日期或行事曆聯動鬧鐘可在編輯器使用「略過下一次」。已有尚未到期的略過項目時不能再略過另一日期。

## 裝置同步狀態

在 `/schedules#devices` 查看裝置；帳密模式依目前授權列出，尚未回報的裝置也會顯示。每張卡片會顯示有效名稱、自報名稱、類型、註冊／最後回報時間、韌體與版本、能力及能力回報時間。可修改並儲存管理名稱（非空白、最多 100 字元）；裝置再次註冊或回報不會覆寫此名稱，目前不能清空管理名稱。未回報的資料顯示「未知」，能力為 `false` 才表示裝置自報不支援；這些資訊不代表實機驗證結果。

按「要求同步」只代表伺服器排入指令。裝置要先輪詢回報狀態、取得 `sync` 指令，完成下載、驗證及保存後再回報 ACK。畫面區分未要求、等待確認、裝置已確認及確認逾時，並列出要求與確認時間。滿 300 秒仍未確認會顯示逾時，但指令仍保留，遲到的相符 ACK 仍可確認；重複要求沿用同一筆指令，不重設等待時間。裝置離線時不會立即完成。

更新列表失敗時保留上次成功資料並標示尚未更新；每 15 秒的列表自動更新與頁內切換語言會保留未儲存的名稱草稿、輸入焦點及選取範圍；重新載入整頁或重開頁面不保留草稿。`online` 僅表示 120 秒內曾回報；ACK 與版本回報不是實際響鈴或畫面更新成功的證明。契約與範例見[裝置 API](server-api.md#狀態與同步確認)。

透過六碼加入的 schema 3 裝置以逐台憑證認證，可在裝置卡片按「刪除授權」；尚未回報時改名與同步停用，仍可刪除授權。舊 self 裝置使用自報 ID 與共用 `DEVICE_API_TOKEN`，移至頁面底部預設收合的「舊式裝置／歷史紀錄」，開合狀態在本頁自動更新與切換語言時保留，但不提供逐台撤權；既存未標來源的殘留記錄不會自動猜測刪除。觀察記錄不能代替授權；單純開啟時鐘頁不會自動加入。停用保留憑證與記錄，恢復後可用原憑證重新連線；移組保留裝置 ID、名稱、能力與 ACK，不重新消耗加入名額。失效或歷史還原要求重加入的裝置不能直接恢復，須移除授權後重新輸碼。群組本身停用時仍無法取得私人內容。

## 夜間模式與離線使用

「顯示設定 → 時間格式」可選擇 24 小時制或 12 小時制（上午／下午），並同步套用至時鐘、鬧鐘、行事曆提醒與夜間時段的顯示及輸入。預設維持 24 小時制；切換格式不會改變已設定的實際時間。

自動夜間模式可設定每天的開始、恢復時間、夜間亮度或黑畫面。它只調整網頁顯示，不會變更裝置背光或自動鎖定；手動黑畫面優先。

時鐘頁先啟動基本時間、日期與星期，再載入連線、鬧鐘及離線快取功能。已載入且在前景執行的頁面，遇到連線失敗、API 拒絕或可選功能錯誤時仍會計時；瀏覽器儲存不可用不會阻止基本時鐘。損壞的瀏覽器／API 顯示設定會整包忽略，沿用最後有效設定；首次載入沒有有效設定時使用預設值。切換 Server URL 或手動重連後，舊連線的延遲回應不會覆蓋目前狀態。

連線與離線快取說明只放在使用者手動開啟的連線面板，不會因網路或快取失敗在主時鐘自動彈出警告或展開面板。使用者明確設定的亮度 0、手動黑畫面、夜間黑畫面仍照常生效；它們隱藏畫面時，底層時間仍持續更新。這些保底行為不代表瀏覽器被系統暫停、鎖屏或尚未載入頁面時仍可執行。

自架版要離線重新開啟，需要 HTTPS 或 localhost，以及支援的瀏覽器。一般 `http://區網IP` 無法準備離線快取，但已載入的頁面仍可繼續計時。快取只包含時鐘頁與顯示資源，不包含管理頁、API、私人行事曆或伺服器提醒。

## 備份、資料與更新

管理頁可下載與匯入 JSON 備份。匯入會在驗證與確認後，取代伺服器顯示設定和手動提醒。上限為 1 MiB、1,000 筆提醒、每筆 1,000 字元。匯入前資料保存在 `webclock_state/before-import.json`，每次匯入都會更新。

管理頁的 version 1 JSON 備份仍只包含設定與手動提醒，不包含智慧排程、裝置、私人行事曆網址、`.env` 或瀏覽器本機提醒；既有匯入與 `before-import.json` 行為不變。

### 損壞的伺服器顯示設定

若 `settings.json` 含無效 JSON、UTF-8 或顯示值，伺服器會記錄檔案路徑與錯誤類型，以正常畫面、亮度 100%、UTC+8、部署預設語言與 24 小時制啟動，不套用夜間模式；整包損壞設定會被忽略。啟動不修改原檔，也不宣稱恢復不存在的最後有效設定。合法的亮度 0、手動黑畫面與夜間設定仍照常載入。

管理者可在顯示設定重新保存，或匯入有效的 version 1 備份。寫入前會先把損壞原檔的完整位元組保存為同目錄下唯一的 `settings.corrupt-*.json`（權限 600），再原子替換 `settings.json`。留存或保存失敗會回報失敗並保留原設定及記憶體狀態；匯入失敗沿用原有提醒回復流程。留存檔由主機管理者保管，不會自動刪除，也不包含在管理頁 JSON 匯出中。

此復原僅限顯示設定。檔案權限／I/O 錯誤仍須修復；授權資料損壞仍拒絕啟動，不會切回免登入。更新器的損壞資料預檢仍會拒絕更新，應先修復設定再重試。

### 主機端完整資料備份與還原

Linux／macOS 可用已安裝 WebClock 相依套件的 Python 執行 `scripts/backup_clock.py`。此工具保留現有單一資料空間的 `.env`、舊 `manual_notes.json`、預設與自訂狀態目錄，以及自訂提醒檔案，包含其中的智慧排程、裝置與 `calendar.json`。備份不含程式、venv、服務執行時的環境變數覆寫、systemd unit、Docker 設定或瀏覽器 localStorage；搬移主機時需另外保存並準備相同版本的程式與相依套件。

**建立與還原前，先停止所有會寫入資料的服務、容器與其他程序。** `--stopped` 只是操作者確認，工具不會自動停止或啟動服務。以下在安裝目錄執行；使用能讀寫資料的帳號，必要時使用管理權限以保留原檔案擁有者。每次建立的備份與還原前副本目錄都必須尚不存在，且不得與資料路徑重疊。

```bash
mkdir -p -m 700 "$HOME/private-webclock-backups"
venv/bin/python scripts/backup_clock.py create "$HOME/private-webclock-backups/backup-001" --project "$PWD" --stopped
venv/bin/python scripts/backup_clock.py verify "$HOME/private-webclock-backups/backup-001"
```

需要還原時，確認全部寫入程序仍已停止，再執行：

```bash
venv/bin/python scripts/backup_clock.py restore "$HOME/private-webclock-backups/backup-001" --project "$PWD" --stopped --yes --rollback-dir "$HOME/private-webclock-backups/before-restore-001"
```

`create` 建立權限 `700` 的備份目錄與 `600` 的 `manifest.json`，保存後以 SHA-256 核對檔案；`verify` 只檢查備份，不需停機。**備份未加密，內含私人網址與憑證**，請放在專案外的私人目錄並限制存取。專案內僅 `.webclock-backup*` 名稱已排除於 Git，其他任意備份目錄不會自動忽略。符號連結與特殊檔案不支援。

目標資料路徑只依目標主機的有效環境、`.env` 與明確傳入的 `--state-dir /目標/狀態目錄 --notes-file /目標/提醒.json` 選擇，不採用備份來源主機的路徑。若服務以環境變數覆寫路徑，請在 `create` 與 `restore` 明確指定實際路徑；原本使用自訂位置的備份，還原時也須指定對應目標，保持相同的包含關係與資料根目錄內的相對路徑。僅在備份含 `.env` 且目標資料路徑不同時，工具才會調整其中的 `WEBCLOCK_STATE_DIR`／`NOTES_FILE`，其餘設定保留；來源若只靠執行時環境變數而沒有 `.env`，啟動前需另外重設該環境。Docker 請先停止容器，再於已安裝相依套件的主機 Python 執行，指定主機掛載路徑，不使用容器內的 `/app/...` 路徑；若使用 Docker volume，先確認其實際主機資料位置。

`restore` 必須提供 `--yes` 與全新的 `--rollback-dir`，先保留還原前完整副本，再替換目標資料；一般內容在備份中不存在時也會還原成不存在；授權 marker、秘密及憑證依前述安全還原規則處理，不得降低保護模式。失敗會嘗試回復，停電不會自動續作。若回復不完整，保持服務停止並保留還原前副本與 `.webclock-restore-*` 暫存資料，確認狀態後再處理。檔案複製會保留原數字 UID／GID；以管理權限還原到新主機或外部目錄後，尤其須確認服務帳號可通過父目錄並讀寫資料。成功後由操作者檢查資料、路徑與權限，再手動啟動服務。這不代表 Raspberry Pi、Docker 或 iPad 已完成實機驗收。

### 更新程式

安裝與更新入口見[安裝指南](installation.md#update)；原生 HTTPS 安裝不適用下方只支援 HTTP 健康檢查的 Linux 更新器。

Docker 取得新版程式後，重新執行：

```bash
docker compose up -d --build
```

由 Linux 安裝腳本建立的服務可執行：

```bash
sudo bash update_clock.sh
```

更新器要求 Git 工作目錄乾淨且可 fast-forward，並會在停止服務前檢查資料路徑、備份程式環境與狀態資料。更新失敗時會嘗試還原；若無法完整還原，請保留 `.webclock-update-*` 目錄及其中的 `manifest.json`、`failed-data/`、`failed-venv/`。更新期間不要修改管理頁資料，也不要把本機測試視為 Raspberry Pi 實機部署已驗證。

第一次從舊版更新器升級時，請保持舊服務執行，並在追蹤 `origin/main` 的安裝資料夾中執行：

```bash
git fetch origin
updater_file="$(mktemp /tmp/webclock-updater.XXXXXX)"
git show origin/main:update_clock.py > "$updater_file" &&
    sudo python3 "$updater_file" "$PWD"
```

這個入口會先載入新版更新器，完成檢查與備份後才切換程式。不要先執行舊更新腳本、`git pull` 或覆蓋安裝。非 Git 安裝無法自動還原被覆蓋的原始碼，停電後也不保證自動續作。

本機驗證、iPad mini 1／iOS 9 待驗收步驟，以及 2027 年之後工作日資料維護方式，見[第一階段驗收紀錄](phase1-acceptance.md)。
